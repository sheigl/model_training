## Minor Issues (Non-blocking)

### 1. `version` type inconsistency in `_dict_to_template_config`
**File**: `common.py:160`

```python
# YAML loader path always produces a string "1"
version=str(doc.get("version", "1")),
```

The `TemplateConfig.version` field is annotated as `int | None`, but the YAML path stores `"1"` (string) while the MongoDB path preserves the integer. This works at runtime (Python is dynamic), but static type checkers will flag it, and any code doing `isinstance(tc.version, int)` would fail for YAML-loaded templates.

**Suggestion**: Normalize to a consistent type — either always store as `str` (since YAML has no real versioning) or convert MongoDB integers to strings in the shared conversion path. A one-line fix:
```python
version=str(doc.get("version", "1")) if "yaml_content" not in doc else str(doc.get("version"))
```

### 2. Dead code branch in `_load_templates_from_source`
**File**: `base_generator.py:286`

```python
return result if result else None
```

Since `self.TEMPLATES` is guaranteed non-empty (validated at line 247–248), `result` will always be a non-empty list. The `else None` branch is dead code. This is harmless but misleading — it suggests the method can return `None` from the YAML path when it cannot.

**Suggestion**: Simplify to `return result`.

### 3. `GENERATOR_FLAGS` in `main.py` is now mostly dead code
**File**: `main.py:86–114`

The `GENERATOR_FLAGS` list was originally used to drive generation of per-generator version flags (`--<slug>-template-version`, `--<slug>-validator-template-version`). Those flags were removed in Story 005, but the registry list remains with no active consumer. It's kept as documentation but adds maintenance burden.

**Suggestion**: Either remove it or add a comment noting its purpose is now documentation-only.

## Highlights (Positive Observations)

1. **Backward compatibility is byte-identical**: When `yaml_loader=None` and `template_store=None`, `_load_templates_from_source()` returns `None`, causing the caller to use class-level `TEMPLATES` constants — exactly the pre-migration behavior. Verified by `test_select_templates_yaml_absent_falls_back_to_class`.

2. **MTG brace preservation is bulletproof**: The consistent use of `str.replace()` instead of `.format()` across both validator prompt builders (`query_model.py:458–462`, `query_model.py:544–554`) and the regression tests (`test_qa_validation_prompt_store_with_mtg_braces`, `test_card_validation_yaml_loader_preserves_mtg_braces`) correctly handle `{T}`, `{C}`, `{W}`, etc.

3. **`requirements_base` list structure preserved**: `shared.yaml` stores it as a YAML list (lines 62–94), `_get_shared_entry` in the loader handles lists explicitly (line 199), and tests verify `isinstance(scaffold["requirements_base"], list)` with ≥8 items.

4. **Scaffolding cache mapping is complete**: `_CACHE_KEY_TO_YAML_KEY` correctly maps all 5 cache keys to YAML keys, and `init_scaffolding()` precedence (YAML → MongoDB → no-op) matches the design doc exactly.

5. **Test coverage is thorough**:
   - `test_yaml_template_loader.py` — 28 tests covering load, missing files, malformed YAML, aliases, shared scaffolding/validators, real file loading
   - `test_cli_templates_dir.py` — 13 tests verifying flag parsing, version-flag removal, preset/count flags still present
   - `test_seed_templates_yaml.py` — 14 tests covering generation, CLI path, deprecation warning, round-trip loader compatibility
   - `test_template_loading.py` — extensive coverage of store-present/absent/YAML paths, validator resolution with real files, scaffolding cache behavior

6. **Seed script `--to-yaml` produces valid, loadable YAML**: The round-trip test (`test_generated_yaml_loadable_by_yaml_template_loader`) verifies that files generated by the seed script load correctly through `YamlTemplateLoader`, including scaffolding, validators, and per-generator templates.

7. **Clean separation of concerns**: `TemplateStore.to_template_config()` is reused via `_dict_to_template_config()` for both MongoDB and YAML paths — DRY and consistent.

## Recommendations for Future Improvement

1. Consider adding a schema validation step in `YamlTemplateLoader._load_yaml()` or in the seed script to catch structural errors (missing `template_id`, wrong types) at load time rather than at template-selection time.
2. The dead `GENERATOR_FLAGS` list could be converted into a proper module-level constant with a docstring, or removed entirely — consistency would help future maintainers.
