# Technical Plan: Seed Script Removal and Migration Helper

## Overview
Repurpose `seed_templates.py` from a MongoDB seeder to a YAML generator. The script's existing extraction logic is valuable and well-tested; it should be adapted rather than deleted.

## Architecture Decisions

### Decision 1: Repurpose with `--to-yaml` flag (recommended)
Rather than deleting the script, add a `--to-yaml` mode that writes YAML files instead of seeding MongoDB. This preserves the extraction logic and test coverage while serving the new workflow.

Rationale: The extraction functions (`extract_shared_blocks`, `extract_legacy`, `extract_validators`) are pure Python → dict transformations that work identically regardless of output format. Tests already cover them well.

### Decision 2: YAML files committed to repo
The generated YAML files are checked into version control. Contributors who modify Python constants can regenerate YAML via the script, but normal development edits YAML directly.

## Files to Modify

### Modified files
- `training_data/generate_synthetic_data/seed_templates.py` — add `--to-yaml` mode, remove MongoDB seed logic from default path
- `tests/test_seed_templates.py` — update tests for new behavior

### New files (generated by script)
- `training_data/generate_synthetic_data/templates/shared.yaml`
- `training_data/generate_synthetic_data/templates/comparison_validator.yaml`

### Task 4: Implement YAML file structure
The `extracted_data` dict from existing extraction functions has this shape:
```python
{
    "scaffolding": {"system_message": "...", ...},
    "generators": {
        "combo_queries": {"templates": {...}},
        ...
    },
    "validators": {"qa_validation": "...", "card_comparison": "..."}
}
```

Map to YAML files:
- `shared.yaml`: scaffolding + validators section
- `{generator_slug}.yaml`: per-generator templates
- `comparison_validator.yaml`: card comparison validator (if not in shared)

## Testing Strategy
- Run script with `--to-yaml --output-dir /tmp/test_yaml` and verify all expected files are created
- Diff generated files against manually-written reference files (from Story 001 plan)
- Run full test suite: `pytest training_data/generate_synthetic_data/ -v`

## Risk Assessment
- **Low risk**: The extraction logic is pure and well-tested. Adding YAML output is a new code path, not a modification of existing logic.
- **Note**: If the script is repurposed, the MongoDB seeding path should be kept but deprecated (with a warning) to avoid breaking any external users during transition.
